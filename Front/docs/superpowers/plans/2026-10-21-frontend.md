# 正式前端 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task, with a final independent review.

**Goal:** 在 Front 中交付独立可运行的暗色 Vue 3 前端；先完成前端，再按接口契约对接 FastAPI。
**Architecture:** TypeScript 域模型、统一 service、demo/api 两套适配器、Pinia 身份状态与 Vue Router 权限守卫；页面不直接访问 localStorage 或拼接口。
**Tech Stack:** Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、ECharts、markdown-it、DOMPurify、Vitest。
**Spec:** ../specs/2026-10-21-front-design.md；原始需求 F:/vibecoding/知识库管理平台.md。

## Global Constraints
- 源代码位于 D:/Knowledge_Base_Management_Platform/Front，沿用暗色与左右贯通登录点阵，不重设计已认可版式。
- 默认拒绝；四维授权 OR；功能权限与数据权限同时检查；管理员无内容旁路。
- 三角色默认首页和菜单不同；运行模式持续可见；本地演示不可冒充真实解析、鉴权或 AI。
- api 模式失败必须报告错误，不降级为 demo；密钥只属于后端。
- 各模块小文件分工；原型与历史设计稿保留。

## Review Focus
- 身份被停用、角色权限变更或知识授权撤销后，旧会话与引用不能泄露内容。
- 无授权不是无命中；FAQ 缓存也必须检查来源权限及发布状态。
- 上传取消/刷新、部分失败、目录相对路径、并发限制须真实反映状态。
- SSE 的 UTF-8、多块事件、结束与错误及取消都须处理；Markdown 禁止脚本与危险链接。
- 自引用部门/角色删除关联、最后管理员保护、缺口取消建档不可提前解决。
