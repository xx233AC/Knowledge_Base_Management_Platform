# 知识库管理平台：前端设计与实施方案

日期：2026-10-21

## 1. 已确认的任务与交付边界

- 总目录：`D:\Knowledge_Base_Management_Platform`；本阶段目录：`Front`。
- 使用当前 VS Code，采用 Vue 3，优先完成前端。后端另行开发。
- 依据用户提供的《知识库管理平台.md》与会话中确认的六大模块实施，不增加商业营销页或无关模块。
- 使用场景：小团队内部实际使用；允许云端模型 API；MinerU 使用远程在线 API。
- 后续后端：FastAPI；PostgreSQL/pgvector、Redis、Worker 等由后端阶段接入。
- 本阶段交付全部页面、前端交互、权限展示、演示数据适配层、真实接口调用层及运行文档。前端不能代替服务端鉴权、真实解析、向量索引和模型生成。
- 当前已完成独立 Vue 3 + TypeScript 前端工程，包含三角色、各业务页面、本地演示适配器与 API 适配器。真实后端尚未开发和联调；早期动态原型保留为设计参考。

## 2. 视觉方向

现代企业工具为主，轻像素元素为辅。按用户最新要求切回暗色界面：炭黑背景、深灰面板、细致的层级与表格对齐，知识状态和图表使用柔和的青绿色。

- 名称沿用「知识库管理平台」，像素书页作为项目标识，不另造产品品牌。
- 主背景 `#111414`；面板 `#1a1e1d`；次级表面 `#262d2a`；正文 `#e6ede9`；次要文字 `#afbeb6`；辅助文字 `#9eafa5`；数据强调 `#83c8ab`；分隔线 `#35403b`。
- 主操作使用柔和青绿 `#83c8ab` 配深色文字 `#12271d`；次操作使用深灰绿填充；警告使用暗琥珀背景 `#38301e` 和浅色文字 `#e8c477`，错误采用暗红底与浅红字。
- 卡片/控件圆角 4px，整体方正。像素元素用于标识、少量图形端点及局部角标，不使用游戏字体渲染中文正文。
- 字体：Inter 用于拉丁字符和数字，中文使用系统中文无衬线；正式代码阶段本地打包需要的字体，避免依赖外部字体网络。
- 标题约 24–26px；正文 14px；辅助信息 12–13px；数值使用等宽数字特性；主要点击区域至少 40px，移动端至少 44px。
- 正文与管理操作区不铺动态纹理、发光、玻璃模糊或背景渐变。登录页左右共用一层低对比像素点阵，表单区域使用透明底板，输入框使用深灰实底保证可读性；状态同时使用文字说明。
- 保留 taste-skill `framed-sheet` 的平齐框架与现有页面排布，按最新要求将明暗色阶切回暗色；方正边角依据轻像素偏好保留。早期浅色 PNG 仅作为历史版式参考，当前主题以可运行原型为准。
- 特有界面元素：混合权限摘要、知识引用定位、导入处理阶段；让知识与权限本身构成产品特征。

### 2.1 用户补充的 UI 设计 Skill

来源：https://skillhub.cn/skills/user_865e3592/ui-new ，版本 1.0.0，包内名称为 `ui-design-system`。已阅读正文及配色、布局参考，以文档方式参考，未运行其安装脚本或修改全局技能源。

- 使用 4px 基准和 8px 主节奏，间距采用 4/8/12/16/24/32/48px。桌面内容边距统一 28px（7 个基准单位），移动端 16px。
- 颜色按背景、面板、文字、强调、成功、警告、错误、边框、焦点定义语义 token；文字与其背景逐项检查，常规正文目标至少 4.5:1。
- 核心控件均包含默认、悬停、按下、聚焦、禁用、加载状态；错误不能只改变颜色，须有错误文本和关联字段。
- 按钮和可点击项显示轻微背景/按压反馈；密集表格行不整体位移；键盘焦点为清楚可见的边框/轮廓。
- 加载时保持最终布局；使用静态骨架或轻量透明度反馈。弹窗与抽屉转场约 150–200ms，并响应减少动态效果设置。
- 移动端至少 44px 触控区域，所有操作有文字或可访问名称；表格在窄屏转为包含同等关键信息的两行记录，不能只隐藏授权和状态。
- 对技能中的紫色模板、大圆角、玻璃模糊、额外渐变等示例不直接套用：它们是通用示例，当前以用户要求的轻像素工具风格和已选视觉系统为准。
- 增加 `04-components-responsive.png` 作为组件状态与移动端布局设计参考。
- 2026-10-21：用户明确将黑色改为浅色，全部页面及组件样板同步使用浅色语义 token；功能、布局与演示数据不变。
- 2026-10-21：用户随后要求切回暗色系，可运行原型的五个场景同步切换为暗色语义 token；登录页左右背景与点阵贯通。

### 2.2 React Bits 参考与已实现动效

用户参考：https://reactbits.dev/ ，官方 Vue 版本：https://vue-bits.dev/ 。以下效果已落实为 `docs/design/05-motion-preview.html` 中的可交互原型，当前使用暗色主题。

| 场景 | 实现的变化 | 交互与约束 |
|---|---|---|
| 登录页 | 全页共享方形点阵响应指针、书页与知识节点图形的像素转场 | 左右背景贯通；登录表单稳定可读；悬停、聚焦、点击可播放图形切换 |
| 看板 | 指标平滑变化、折线绘制、柱条入场 | 700ms 数值过渡，响应时间保留小数；数据来自同一批演示日志；不会伪造业务增长 |
| 知识列表 | 行依次入场、演示新增记录反馈、详情面板 | 搜索/分类/状态筛选和分页可实际操作；插入记录只影响本地预览 |
| 导入中心 | 五阶段指示、逐文件阶段状态、完成反馈 | 明确为本地播放；可选择/拖入文件但不上传；可停止，停止后旧定时器不能继续推进 |
| AI 对话 | 消息入场、模拟流式输出、引用与受限提示 | 可重播、提问、停止、新建/切换演示会话；文本按纯文本展示，用户输入不会解释为 HTML |

- 普通界面过渡约 150–260ms，列表错开约 35–50ms；像素转场约 540ms。阅读区域无持续运动。
- 顶部设计工具栏可以切换五个场景、重播当前动效及减少动态效果。
- 默认响应系统 `prefers-reduced-motion`：数值直接显示最终值、点阵静态、CSS 过渡关闭。用户可显式切换动态偏好。
- 点阵以 Canvas 绘制；仅在入场、指针响应及归位时绘制，离屏、隐藏标签页、卸载时停止相应帧循环和监听。
- 原型使用 Vue 3.5.44，运行文件已内嵌，可脱离 CDN 和服务器打开；没有引入 React。图形和动画为针对本项目编写的实现，参考上述组件的交互思路。
- 原型中的登录、导入、问答均带模拟标识，不调用 MinerU、不生成向量、不发送账号或文档内容。

## 3. 布局与响应式

- 桌面：左侧约 224px 分组导航，顶部 64px 上下文条，内容区左右约 28px。
- 顶栏展示当前页面位置、运行模式和当前用户。无功能的搜索、通知、设置入口不加入界面。
- 导航分组：工作台（看板、AI 对话）；知识管理（知识单元、导入中心）；组织权限（用户、角色、部门）；知识沉淀（推荐审核、已发布 FAQ、知识缺口）；底部个人中心与退出。
- AI 工作台桌面采用会话列表、消息区、引用区三栏；窄屏优先消息，历史与引用通过抽屉展开。
- 平板侧栏折叠，表格保留关键列并允许表格内部滚动。移动端侧栏为菜单抽屉，筛选收拢，编辑表单单列。
- 390、768、1440px 验证；页面本身不得横向溢出。所有弹窗可键盘操作，保留可见焦点，关闭后恢复焦点。

## 4. 页面、功能与路由

| 页面 | 路由 | 必须实现的能力 |
|---|---|---|
| 登录 | `/login` | 用户名/密码、校验、加载、失败提示；未登录保护 |
| 个人中心 | `/profile` | 用户名、姓名、部门、角色、当前操作权限、退出 |
| 数据看板 | `/dashboard` | 访问次数、UV、知识量、Token、平均耗时；两类排行；日/周访问、Token 走势及响应时间分布 |
| 用户管理 | `/org/users` | 列表、筛选、新增、编辑、部门/角色分配、启停用、重置密码 |
| 角色管理 | `/org/roles` | 新增/编辑角色名称编码说明；菜单与按钮/AI 操作权限树，保存和反馈 |
| 部门管理 | `/org/departments` | 部门树、新增/编辑/删除、父部门、负责人和成员；阻止循环挂载及有子部门时误删 |
| 导入中心 | `/knowledge/import` | 拖拽、单文件、多文件、目录；格式验证；逐文件状态、总体进度、失败原因；导入结果跳转 |
| 知识单元列表 | `/knowledge/units` | 标题、分类、状态筛选和分页；编号、标题、格式、权限摘要、创建人、更新时间、状态；选择和批量删除 |
| 新建知识 | `/knowledge/units/new` | 标题、分类、正文、标签、附件、状态、默认无授权；保存后成为独立单元 |
| 知识详情 | `/knowledge/units/:id` | 内容、元信息、授权摘要、来源、版本记录；有权限时查看附件和引用定位 |
| 知识编辑 | `/knowledge/units/:id/edit` | 编辑、版本记录、状态调整和授权配置；未保存变更离开提示 |
| AI 工作台 | `/ai/chat/:sessionId?` | 新建/历史/多轮会话；输入与流式 Markdown；引用卡片、权限提示、无命中与错误状态 |
| FAQ 推荐审核 | `/settlement/faqs/recommendations` | 推荐频次、关联知识、建议答案；编辑答案、审核通过、驳回 |
| 已发布 FAQ | `/settlement/faqs/published` | 查询、维护标准问答、查看关联来源和缓存状态；不可伪造远端缓存生效 |
| 知识缺口 | `/settlement/knowledge-gaps` | 问题模式、样本、频次、最近提问时间和状态；预填创建知识，关联后更新缺口 |

状态字段在接口层集中定义；演示生命周期采用草稿/已发布/已归档。导入任务的等待/上传/解析/切分/向量化/完成/失败是另一套状态，不与知识发布状态混用。

## 5. 共用组件

- 页面标题与动作区、筛选栏、空状态、错误重试、确认弹窗、抽屉/对话框、分页、加载占位。
- `PermissionSelector`：全局开关，多选部门、角色、人员；支持混合授权，明确说明任一条件匹配即可；空选择明确为默认不可访问。
- `PermissionSummary`：列表中简明展示四维授权，不用隐藏功能模拟真实鉴权。
- `ImportTaskList`：每个文件独立结果，批次进度从文件状态计算。不能获得解析百分比时展示阶段或不确定进度。
- Markdown 显示必须清洗 HTML；代码、链接、表格需可阅读，外部链接安全打开。
- 知识来源卡片与权限提示卡片独立；拒绝内容不展示正文、摘要或未经授权的标题。
- 当前源文档是一篇知识单元；内部检索分块不在首期新增独立管理模块。可用的页码、章节作为引用位置展示。

## 6. 权限交互

- 登录保护、路由权限、动态导航、按钮权限和数据访问展示必须统一使用权限工具与当前身份数据。
- 操作权限示例：`dashboard.view`、`org.users.manage`、`org.roles.manage`、`org.departments.manage`、`knowledge.read/create/update/delete/import/permissions`、`ai.access`、`faq.review/manage`、`gaps.manage`。
- 数据权限是 global、department、role、user 的 OR；功能权限与数据权限同时检查。global 只表示系统内适格登录用户可访问。
- 演示身份至少包括系统管理员、知识管理员和普通提问者，展示不同菜单及按钮。演示账号的样本读取权由明确授权实现，不默认赋予管理员内容旁路。
- 当前需求部门为单部门归属，演示按精确部门匹配。下级部门是否继承、生产管理员是否具有额外内容管理权需后端详细设计再明确，前端接口预留。
- 前端模拟只用于交互演示，不能作为安全措施。生产必须由后端验证；身份不能通过前端随意指定 `user_id`。
- FAQ 和历史对话在演示适配层也遵循权限；当前无权的引用只显示受限提示，不回显其正文。生产依赖后端提供经过校验的响应。

## 7. 演示数据与真实接口

- 使用统一的 service 接口与两个适配器。配置 `VITE_DATA_MODE=demo|api`，运行时持续显示当前模式。
- demo：本地模拟交互与本地持久化，仅使用虚构样本。登录、上传状态、流式回复均明确为模拟；PDF 不在浏览器假装被 MinerU 解析。
- api：调用 `VITE_API_BASE_URL`；网络失败显示错误，不自动回退为演示成功。模型和 MinerU 密钥绝不放在前端。
- 主要接口路径与需求文档保持一致。原文未列完整的会话、导入任务进度、CRUD 补充接口，统一写入接口契约文档，并标注为后端待实现的约定。
- AI 使用 `fetch` POST + SSE 解析；正确处理跨网络块事件、结束/错误、取消与重复提交。demo 通过同一事件模型输出带标识的模拟回答。
- 目录上传保留相对路径，仅在用户选取的目录内处理；上传数量/大小限制配置化；不支持的文件显示明确原因。
- 真实导入进度由后端轮询获取；浏览器刷新后可重新拉取任务。Worker、MinerU 和向量化均属于后端职责。
- 本地演示变更应可持久化，并有明确的演示数据重置入口；重置需要确认，不影响真实 API 模式。

## 8. 数据和流程闭环

- 样本：12 个知识单元（9 已发布、3 草稿）、8 个用户、4 个部门、3 类初始角色，以及 FAQ 和知识缺口样本。所有人名、文档均为虚构。
- 看板样本问答日志共 42 轮，7 天访问量为 `[4,6,5,8,6,7,6]`；UV、Token、排行和耗时分布从同一日志数据生成，禁止分别硬编码互相矛盾的数字。
- 设计稿中的看板数值仅为标注过的演示示例；代码阶段所有汇总由样本记录计算。新增演示问答后，相关统计应更新。
- 知识新增/编辑/删除后列表立即同步；详情编辑有版本记录；批量删除展示影响范围并确认。
- 导入任务完成后能进入生成的演示知识详情，但必须说明该过程没有调用真实 MinerU。
- FAQ 审核通过后进入已发布列表；其演示缓存状态明确标为本地模拟；驳回留有状态记录。
- 缺口创建知识时预填标题、问题和关联关系；取消创建不能提前将缺口标为已解决。
- 无权访问与真正无命中分开呈现，不能把无权资料自动计为知识缺口。

## 9. 技术组织（已搭建）

- Vue 3、TypeScript、Vite、Vue Router、Pinia。
- Element Plus 负责复杂表单、树、对话框与表格交互；统一主题覆盖，不沿用默认整页模板。
- ECharts 展示真实数据驱动的统计图；单系列不加多余图例，数值有单位和清晰刻度。
- markdown-it + DOMPurify；HTTP 使用统一请求层，SSE 使用独立流式适配器。
- 目录边界拟为 `src/views`、`components`、`layouts`、`router`、`stores`、`services`、`types`、`styles`、`demo`；不把所有功能堆入单个组件。
- 前端开发服务器仅用于本地开发；构建结果后续由 Nginx 托管。后端项目不在本阶段创建。

## 10. 验证与完成标准

- 类型检查和生产构建通过。
- 验证登录与路由保护、各角色菜单/按钮差异、四维权限 OR 与默认拒绝、CRUD、批量删除和持久化。
- 验证文件选择/目录/拖放、单文件失败、多文件进度和结果跳转；明确模拟边界。
- 验证 SSE 分片解析、Markdown 清洗、引用/拒绝卡片、空回复和错误中断。
- 验证 FAQ 审核闭环、知识缺口创建后关联、看板汇总与日志一致。
- 浏览器逐页检查，覆盖 1440/768/390px；无页面级横向溢出；无控制台错误；表单/模态键盘可用。
- 单元测试聚焦权限、统计、状态流转、SSE 和数据适配；端到端测试覆盖关键业务链路。
- 文档交付：启动说明、演示账号、真实/演示配置、接口契约、需求验收映射与尚需后端接入的项目。
